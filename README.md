# Diagram Studio

Браузерный редактор диаграмм: React 19, TypeScript 6, Vite 8, React Flow 12, Zustand 5, Tailwind 4. Работает без регистрации и backend API. Доступны IDEF0, блок-схемы и физические ER-диаграммы PostgreSQL 18.

## Запуск

Требуется Node.js **24.13+ в ветке 24 LTS** (версия задана в `.nvmrc` и `package.json`).

```bash
npm ci
npm start
```

Откройте **http://127.0.0.1:5173/**. Сервер должен оставаться запущенным в терминале. `npm run dev` запускает тот же редактор. Порт фиксирован: если занят, Vite сообщает об ошибке, а не переходит незаметно на другой адрес.

### Если браузер сообщает connectionfailure

1. Запустите `npm start` из каталога проекта и проверьте вывод терминала.
2. Используйте `http://127.0.0.1:5173/` (HTTP, не HTTPS).
3. После обновления зависимостей остановите прежний сервер и запустите `npm run dev -- --force`, затем обновите страницу.
4. Если порт занят, остановите старый сервер этого проекта. Не завершайте неизвестные процессы.
5. Для другого устройства используйте сетевой адрес компьютера из вывода Vite. Локальное хранилище на этом устройстве будет отдельным.

`localhost`, `127.0.0.1` и сетевой IP — разные адреса хранилища браузера. Чтобы увидеть прежние проекты, открывайте тот же адрес, что использовали ранее.

## Возможности

- стартовая страница со списком локальных проектов, созданием, импортом и удалением;
- несколько независимых IDEF0-моделей, их декомпозиции, блок-схемы и ERD в одном проекте;
- дерево диаграмм и вкладки в общей шапке с названием проекта; закрытие вкладки не удаляет диаграмму;
- сворачиваемые боковые панели, отдельная палитра, инспектор и нижняя панель проверки;
- автосохранение в IndexedDB после завершённых операций с отображением результата и повтором при ошибке;
- сохранение масштаба и положения холста отдельно для каждой диаграммы;
- undo/redo: одно перемещение, изменение текста или удаление группы — одно действие;
- редактирование имени функции на холсте, копирование/вставка, дублирование и выравнивание выделенных блоков;
- внешние IDEF0-стрелки от краёв рабочей области: вход слева, управление сверху, механизм снизу, выход справа;
- прямоугольные маршруты стрелок, настройка смещения маршрута в свойствах;
- JSON, PNG, самостоятельный векторный SVG и векторный PDF; весь проект можно выгрузить в многостраничный PDF;
- кириллица в экспорте: локально включён Noto Sans под SIL OFL, лицензия в `public/fonts/OFL.txt`.

Горячие клавиши: Ctrl/Cmd+S — скачать JSON; Ctrl/Cmd+Z — отменить; Ctrl/Cmd+Shift+Z — повторить; Ctrl/Cmd+C/V — копировать/вставить; Ctrl/Cmd+D — дублировать; Delete — удалить. В текстовых полях работают обычные текстовые команды. Enter или уход из однострочного поля применяет подпись, Escape отменяет ввод. В многострочном тексте Enter добавляет строку, уход из поля применяет изменения.

Копирование переносит выбранные блоки и связи между ними, без вложенных декомпозиций. В контекстной диаграмме допускается одна функция. Корневую диаграмму проекта удалить нельзя; удаление остальных диаграмм с потомками можно отменить.

## Создание IDEF0-стрелок и подписей

В рабочей области нет отдельного белого листа или овальных интерфейсных блоков. По краям находятся зоны «Вход», «Управление», «Выход», «Механизм». Перетащите указатель из зоны на функцию, либо от соответствующей точки функции к краю. Кнопки Input / Control / Output / Mechanism создают стрелку для выбранной функции (или единственной функции диаграммы). Начальная точка внешней стрелки остаётся у края видимой рабочей области при перемещении и масштабировании. В экспорте границы вычисляются по размерам всей диаграммы, независимо от текущего экрана.

Новые функции и стрелки имеют пустые подписи. «Название функции» и «Подпись стрелки» — подсказки, которые исчезают при вводе первого символа и не попадают в JSON/PDF/SVG/PNG. Точное старое значение «Новая функция» при открытии заменяется пустой строкой; пользовательские имена сохраняются. Прежние интерфейсные узлы отображаются как точки на границе, существующие связи сохраняются.

## Блок-схемы

Создайте проект или добавьте диаграмму, выбрав «Блок-схема». В палитре доступны «Начало», «Конец», «Процесс», «Условие», «Ввод / вывод», «Подпроцесс». Перетаскивайте блоки за свободное место у края фигуры; текст редактируется прямо на холсте. Подсказки пустых блоков не записываются в проект и не экспортируются.

Проведите стрелку от точки на любой стороне исходного блока к точке следующего блока. Вход в «Начало», выход из «Конец», связь блока с собой и повтор одинакового перехода запрещены; циклы между разными блоками поддерживаются. Ветви условия можно подписать «Да» и «Нет» на холсте или в свойствах. В свойствах также меняются фигура, текст, заметки и смещение маршрута стрелки. «Подпроцесс» — графический символ, он не создаёт вложенную диаграмму.

Проверка предупреждает об отсутствии начала/конца, недостижимых блоках, тупиках, недостающих ветвях и неподписанных или одинаково подписанных ветвях условия. Незавершённые схемы можно сохранять. Доступны история действий, групповое выделение, копирование, выравнивание и все форматы экспорта, включая общий PDF с IDEF0 и блок-схемами.

## ER-диаграммы PostgreSQL 18

Выберите «ERD» при создании проекта или добавлении диаграммы. «＋ Таблица» открывает редактор структуры; двойное нажатие или кнопка «⋯» открывает его повторно. Изменения применяются одной операцией. Новая таблица содержит колонку `id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`; имя таблицы вводится пользователем.

На холсте показаны схема и имя таблицы, все колонки, типы с параметрами, PK/FK/UQ, NULL/NOT NULL, DEFAULT, IDENTITY, GENERATED, COLLATE, комментарии, индексы и CHECK. Длинные значения сокращаются в карточках; полные значения доступны в структуре и SQL.

В структуре доступны:

- порядок колонок, параметры длины/точности/scale, массивы до шести измерений;
- единый составной PK, отдельный UNIQUE колонки и составные UNIQUE;
- DEFAULT как выражение SQL, IDENTITY ALWAYS/BY DEFAULT, GENERATED STORED/VIRTUAL;
- индексы B-tree, Hash, GiST, SP-GiST, GIN, BRIN, уникальные и частичные индексы, INCLUDE, NULLS NOT DISTINCT;
- именованные CHECK, комментарии и UNLOGGED.

Для одиночного FK перетащите точку колонки дочерней таблицы к точке колонки PK/UNIQUE родительской. Для составных и самоссылочных связей используйте «＋ Внешний ключ»: задайте таблицы и все пары колонок. Поддержаны ON DELETE/UPDATE, MATCH SIMPLE/FULL и отложенная проверка DEFERRABLE/INITIALLY DEFERRED. Двойное нажатие на связь открывает её настройки. Кратности `0..N`, `0..1`, `1` вычисляются из ограничений; обязательное наличие дочерней строки внешний ключ не гарантирует. Для связи многие-ко-многим создайте таблицу-связку с двумя FK.

Кнопка «SQL PostgreSQL 18» выгружает DDL: схемы, таблицы, комментарии, индексы и затем внешние ключи — в том числе циклические. SQL создаёт новую структуру, не является миграцией существующей БД и не выполняется приложением. Структурные ошибки блокируют SQL-экспорт, но не сохранение черновика. Выражения DEFAULT/CHECK/GENERATED и классы операторов для индексов окончательно проверяет PostgreSQL. PNG/SVG/PDF также поддерживают ERD и смешанные проекты.

Каталог основан на [типах PostgreSQL 18](https://www.postgresql.org/docs/18/datatype.html); параметры и генерация сверены с [CREATE TABLE](https://www.postgresql.org/docs/18/sql-createtable.html) и [вычисляемыми колонками](https://www.postgresql.org/docs/18/ddl-generated-columns.html). Предлагаются встроенные типы общего назначения, диапазоны, мультидиапазоны, системные ссылочные типы и SERIAL. Псевдотипы не предлагаются как типы колонок. Пользовательские ENUM/domain/composite и типы расширений, секционирование, EXCLUDE/temporal keys, триггеры, политики RLS и обратный импорт существующей БД пока не реализованы.

Для проверки DDL на установленном PostgreSQL 18 в Windows после браузерных тестов:

```powershell
.\scripts\check-er-sql.ps1 -SqlFile test-results/schema.sql
```

Скрипт создаёт отдельный временный кластер внутри `test-results`, использует свободный localhost-порт и останавливает его в `finally`. Существующие базы не затрагиваются. Путь к бинарным файлам задаётся параметром `-PostgresBin`.

## Данные и совместимость

Проекты хранятся в IndexedDB `diagram-studio`, object store `projects`. `localStorage` содержит только настройки рабочей области (вкладки, панели, масштаб).

При первом открытии старый черновик `ulstu-idef0:last-project` проверяется и переносится в IndexedDB. Исходник удаляется только после успешной записи; существующий проект не перезаписывается. Повреждённый черновик сохраняется с сообщением об ошибке.

Формат JSON имеет версию `4.0.0`, диаграммы содержат `type: "idef0"`, `type: "flowchart"` или `type: "er"`. Импорт версий `1.0.0`, `2.0.0` и `3.0.0` поддержан с автоматической миграцией. Проверяются структура, идентификаторы, ссылки и циклы декомпозиции. Неизвестные версии отклоняются. Импорт создаёт отдельную копию проекта и не перезаписывает существующий.

Скачивайте JSON для резервных копий: очистка данных браузера удаляет локальные проекты. Проект хранится на устройстве; облачной синхронизации и совместного редактирования нет.

## Архитектура

- `src/types/project.ts` — оболочка проекта и каталог нотаций; `diagram.ts` — общая модель элементов; `flowchart.ts` — фигуры блок-схем.
- `src/features/project` — проверка файлов, миграции, IndexedDB и состояние рабочей области.
- `src/features/diagram` — модель операций с историей на Immer, преобразование в React Flow и редактор IDEF0.
- `src/features/flowchart` — редактор блок-схем, геометрия фигур для холста и экспорта, проверка алгоритмов.
- `src/features/er` — физическая модель PostgreSQL 18, редактор таблиц и составных связей, каталог типов, валидация, SQL и графический экспорт.
- `src/features/export` — генерация SVG из модели и экспорт в PNG/PDF без снимков HTML.

История хранит неизменяемые версии с совместным использованием неизменённых объектов. Текущее перетаскивание и измерения React Flow живут отдельно от сохранённой модели и фиксируются в конце жеста.

Нотации используют общие операции над графом и отдельные редакторы, геометрию и валидацию. При импорте проверяется соответствие элементов типу диаграммы. Копирование между разными нотациями запрещено. ERD хранит стабильные идентификаторы колонок; переименование не разрывает связи. Удаление колонки и её внешних ключей — одна отменяемая операция.

## Проверки

```bash
npm run lint
npm test
npm run build
npm run test:e2e
```

Браузерные тесты используют установленный Microsoft Edge на Windows; на других ОС сначала выполните `npx playwright install chromium`. Сценарии запускаются в изолированных профилях и не изменяют ваши проекты.

TypeScript оставлен на последнем исправлении ветки 6: установленный typescript-eslint пока требует TypeScript ниже 6.1. Обновлять до 7 следует вместе с поддерживающим его линтером.

## Docker и публикация

```bash
docker compose up --build -d
```

Адрес контейнера: **http://localhost:8080/**. Сборка использует Node 24 LTS, раздача — nginx stable. Для проверки production-сборки без Docker: `npm run build`, затем `npm run preview` и http://127.0.0.1:4173/.

Workflow публикации образа в GHCR остаётся в `.github/workflows/publish-container.yml`. Проверки кода и браузерных сценариев запускаются отдельным CI workflow.

## Ограничения

Ветвление/слияние IDEF0-стрелок через junction-узлы ещё не реализовано. Смещение маршрута не заменяет свободное редактирование всех точек изгиба. PDF размещает каждую диаграмму на одной странице A4; очень большие схемы уменьшаются. В экспорте длинные подписи блоков переносятся и при нехватке места сокращаются многоточием. Основной сценарий интерфейса — работа на компьютере.
